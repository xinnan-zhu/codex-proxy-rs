# v3.29.7

## 修复与改进

- 合并官方 v3.29.6、v3.29.7 及主分支后续修复，改进请求失败、取消、重试和资源释放，避免连接恢复提前耗尽换号预算
- 修复 OpenAI 池化 WebSocket 慢建连被误计为熔断失败，以及插件长流受初始处理期限影响而提前中断的问题
- 隔离不同 OpenAI 账号的关联标识，改进输入轮次识别，并保留可执行文件路径，减少历史内容处理对请求的误影响
- 诊断下载改为 ZIP，包含结构化证据、摘要和说明；保留关键终态观测、采集缺口与输入指纹，便于分析失败和重试
- 业务备份改为流式压缩归档，缩小请求历史造成的备份体积与暂存空间占用；加快历史清理，并修复后台任务恢复后健康状态仍报错的问题
- 账号编辑默认显示已绑定代理的名称，未更改选择时保留原绑定；直连账号显示直连，批量编辑继续支持“保持当前”
- 完善插件请求来源、原始响应观测、正文限制和资源流处理，修复插件管理、密钥用量复制及下载等边界行为
- 更新依赖并修复已知安全问题，优化 Windows Codex 版本检查，避免扫描整个 MSIX 安装包
- 保留本 fork 的账号客户端限制、额度展示、xAI 额度刷新与推理强度记录、模型筛选、每 $1 可跑 M Token 统计、明确标注的估算速率和更新下载代理

## 升级说明

- 插件 RPC 协议由 v4 升至 v5，`upstream_adapter` 能力由 v3 升至 v4。现有插件需使用匹配的新 SDK 重新构建和打包，仅修改清单版本不够；受影响接口需适配字节头、响应元数据和 WebSocket 原文类型，`service_tier` 移至 `observation`
- 插件模型调用和受管 HTTP 出站采用 `responsesMaxDecompressedBodyBytes` 设置，默认 64 MiB；实际出站正文超限时返回 413，不发送上游请求
- 新建业务备份为 `.sql.gz`，使用 `gzip -dc` 解压并通过 `psql` 离线恢复到空目标库；旧 PostgreSQL custom 格式备份仍使用 `pg_restore`
- 业务备份不包含请求明细、诊断与审计日志，历史用量仅保留全局小时汇总，不能恢复历史请求详情、按 Key/账号筛选及延迟分布；需要完整历史请另做整库备份。统计尚未就绪时业务备份会失败，需就绪后重新创建
- 诊断 ZIP 不会补生成历史记录中缺失的证据，分享前请检查包内原始请求、响应及错误内容
