# v3.26.1

## 速率统计

- 修复 Grok 新请求及缺少上游计时的历史请求无法显示速率的问题：优先使用上游响应耗时，缺失时按网关总耗时估算，列表明确标注「估算」，速率面板显示估算样本数
- 升级后重建历史统计时间桶，保留请求记录和原始计时；输出 Token 或可用耗时缺失时仍不生成速率，估算不改写上游计时字段

## 同步官方更新

- OpenAI Responses 的 HTTP/SSE 与 WebSocket 即时转发前导事件和压缩进度，减少客户端等待；仅交付可替换前导且未启用中间件链时保留有界重试，修复 WebSocket 连接寿命限制错误的恢复流程
- 优化大规模历史数据的统计、账号与 Key 用量、精确分页和额度预测，移除固定十万行拒绝条件；修复额度比例回落时预测累计量重置的问题
- 移除账号「最小请求间隔」，并发、排队、额度和冷却限制继续生效
- OpenAI 多账号 JSON 导入逐账号处理并自动分批，单个失败不再阻断整份文件；优化 Codex 隐私规则对长请求的处理
- 管理端会话区分访问凭据与续期凭据，修复会话续期边界；额度预热使用模型目录支持的推理强度
- 管理端 API 请求超时固定为 120 秒，后端观测操作默认保护时限为 120 秒；请求转储保留天数支持小数
- 使用记录耗时按阈值着色，优化隐私规则和模型价格表展示；改进租约、备份清理、S3 探针与在线更新回滚的错误保留，并更新安全依赖

## 升级事项

- 新增官方 `0030` 与定制 `900011` 迁移，创建统计索引、删除请求间隔字段并安排历史统计重建；已发布迁移保持不变。升级前备份数据库，大数据量下迁移会增加启动时间和 I/O，统计桶由后台逐步重建
- 管理 API 和插件设置不再提供 `requestIntervalMs`／`request_interval_ms`；前端不再读取 `VITE_API_TIMEOUT_MS`，后端观测超时可通过 `store.pool.observability_timeout_seconds` 配置
- 使用记录搜索仅按密钥、账号和模型做前缀匹配，请求 ID 和上游 ID 使用精确筛选参数；搜索不再改变顶部统计范围，管理观测接口不再接受路由分组筛选
- 分组费用按当前组成员的留存请求计算；正文、工具活动、压缩进度或未知事件交付后不再透明重放，中间件链不启用可替换前导的重试例外
- 速率估算包含排队、网络及处理等待，与上游耗时计算出的速率口径不同
