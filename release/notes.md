# v3.25.0

## 新增能力

- 支持 OpenAI `ultrafast` 与 `long_ultrafast` 价格档位，内置 `gpt-6-astra` 和 `gpt-6.1-sol` 的短、长上下文 Ultrafast 价目，并可在管理端自定义单价

## 修复与改进

- Responses 流式请求完成准入后，首个业务事件前的等待也每 15 秒发送 SSE 注释保活，覆盖账号等待、中间件处理和前导事件缓冲；心跳保持原有安全重试资格，后续重试可正常记录执行尝试
- 收紧 OpenAI 自动重试范围，普通上游拒绝保留错误与重试提示，交由客户端处理；明确未发送的瞬时建连失败支持有界恢复，包括 TLS 握手 EOF
- 已知模型只路由到明确提供该模型的 Provider，目录刷新失败时保留已有模型归属；未知模型仅在透传候选唯一时发送，Grok 请求不再选择 ChatGPT OAuth 账号
- 修复繁忙 OpenAI 账号因额度观测时刻更新而反复选号冲突的问题；凭据、调度状态和额度结论变化仍重新校验
- 修复持续请求写入时统计投影反复回滚、待处理队列积压的问题，投影提交后再确认对应源版本，保留并发更新供后续处理
- 请求健康可用性与服务成功率统一计入未完成请求，仍排除客户端取消和调用方错误；健康时间线在有效样本不少于 10 个且可用性不低于 95% 时显示稳定，浮层将未完成并入服务失败展示
- 插件中间件等待宿主 `next` 时暂停自身处理预算，返回后恢复剩余时间；请求总期限与取消继续独立生效，避免下游处理较慢时误触发插件超时

## 升级事项

- SSE 首次心跳前保留最终 HTTP 状态与响应头；心跳发出后发生的失败通过 `response.failed` 和 `[DONE]` 返回，HTTP 状态保持 `200`，`Retry-After` 位于 `response.error.headers`，后续响应头无法补发。心跳只覆盖客户端到 CPR 的链路，不延长账号出站代理的读取期限
- 使用旧 SDK 构建的中间件插件需升级 SDK 并重新构建，才能配合宿主暂停 `next` 等待期间的预算；单独升级宿主不能解除插件侧的固定期限
- 多 Provider 配置下，无法确定归属的未知模型不再按 Provider 名称顺序猜选平台；需要透传时，可通过 Client Key 分组限定目标平台
