# v3.21.1

同步官方 v3.21.0 与 v3.21.1，保留本 fork 的定制功能。本说明覆盖从本 fork v3.20.0 升级的全部新增内容。

## 新增功能

- OpenAI 账号亲和支持「严格／优先／宽松」三种模式：严格模式让同一会话共用账号；优先模式优先使用主账号，繁忙或不可用时临时分流并保留原绑定；宽松模式直接按调度策略选号
- 设置页支持调整会话账号绑定保留时长与单请求最大换号次数，默认分别为 24 小时和 3 次，保存后对新请求生效
- Codex Desktop 客户端画像支持填写系统版本，并在预览中展示实际出站值

## 修复与改进

- 错误诊断保留本地原因链、上游错误正文和清理失败，减少重试及错误包装造成的信息丢失，诊断导出保留受控的失败分类
- 日志和请求观测改用有界非阻塞写入，并为失败记录预留容量，减少日志拥堵对请求的影响
- 减少请求副本驻留并优化 XZ 缓冲分配，降低内存占用
- 管理页面首次进入只读取登录状态，业务接口返回认证错误时才续期；并发请求共用续期结果，临时网络或服务故障不再直接清除登录状态
- OpenAI 首字时间按首个非前导输出事件计算，包括输出项等结构事件，跳过响应创建、处理中、心跳、额度控制及失败事件；推理与正文仍分别按实际内容计时
- 用量列表与性能统计的 tok/s 统一按输出 Token ÷ 完整请求耗时计算，避免扣除首字等待后高估速率；已计入的推理 Token 不重复相加或扣除

## 本 fork 功能

- 保留账号「仅限 Codex 官方客户端」、Turn State 字节观测、额度周期费用与重置进度、使用统计模型筛选和系统更新下载代理
- 总费用副标题继续显示每 1M Token 的平均费用；计费不完整时提示实际费用可能更高
- 已移除的按 Turn State 长度阻断功能保持移除

## 升级说明

- 本 fork v3.20.0 可使用此 Linux AMD64 更新包升级，启动时自动执行 `0023_error_details_and_account_affinity.sql` 和 `0024_preferred_account_affinity.sql`，已发布的官方及 fork 迁移保持不变，升级前请备份数据库
- 从 v3.20.0 升级时，已保存过运行设置的记录初始化为宽松亲和；尚未保存过设置的初始记录采用严格模式。希望继续让子代理跟随根会话账号的实例，请在设置中选择「严格」；需要主账号优先、必要时分流，请选择「优先」
- 管理员原有 `admin.session_ttl_minutes` 继续作为不活动期限；新增 `admin.session_absolute_ttl_minutes`，省略时为 30 天。配置模板的不活动期限为 7 天，已有配置不会被自动改写，旧会话重新登录后应用续期策略
- 自行调用管理 API 的客户端需将运维错误字段 `rawUpstreamError` 改为 `errorDetails`；整体保存运行设置时需包含 `openaiAccountAffinity`（`relaxed`／`preferred`／`strict`）、`openaiSessionAffinityTtlHours` 和 `maxAccountRotations`。诊断快照 `schemaVersion` 升为 2，管理端导出诊断包升为 3
- 历史用量的 tok/s 会按新口径重新计算；已记录的首字时间保持原值，新首字判定仅对升级后的请求生效
- 已在源码部署中执行未发布的 `0023_error_details.sql`、`0024_account_affinity.sql` 或 `0025_session_affinity_ttl.sql` 的数据库，不适用上述直接升级路径，请勿改写迁移校验和绕过检查

更新包包含前端、Linux AMD64 二进制、配置模板与封口插件清单，按 Debian bookworm / glibc 2.36 基线构建，供管理端在线更新使用。
