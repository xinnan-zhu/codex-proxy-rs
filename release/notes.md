# v3.14.1

## 新增功能

- 提供独立进程插件系统：支持上传及固定来源安装、制品访问域确认、实例配置、管理页面、版本配置恢复和私有状态；插件可通过公开 SDK 扩展请求中间件、模型路由、调度、用量、请求生命周期及 WebSocket 观察等能力
- 代理管理支持按出口解析地区、城市和时区，一键填入自定义位置；解析失败保留已有输入，并分别展示连接与位置查询结果
- 账号模型列表支持选择并导出完整 Codex 模型目录，保留原生能力字段，可直接用于客户端 `model_catalog_json`；文件名包含套餐与账号名称
- OpenAI OAuth 账号支持选择上游 WS 或 SSE，默认 WS；账号导入和编辑均可设置
- 支持按北京时间设置多个账号预热时段，默认关闭，启用前须显式选择模型；只处理符合额度与状态条件的 OpenAI OAuth 账号，以响应成功终态判定结果

## 问题修复

- 连接建立前的失败按发送状态安全重试，连接容量和基础设施错误不再误伤账号健康状态；保留 WebSocket 退出诊断，将上游 Close 1009 正确归为请求过大
- 分组费用按实际服务账号在执行时的分组归属统计，避免 Client Key 分组与服务账号分组不一致时漏计或错计
- 账号设置保存不再等待上游模型目录刷新，减少保存延迟
- Grok 客户端访问 Codex 上游的兼容限定在专属请求标记和已知指令开场白，普通 Codex 请求保持原有语义；不根据缓存键补造会话或线程请求头
- 修复插件路由拒绝下划线等合法 HTTP 请求头的问题，会话和身份字段继续按权限隐藏；插件启动遇到瞬时文件忙时在启动期限内重试
- 补齐 GPT-6 Sol、Luna 内置价格，并更新后端依赖、管理端组件和容器基础镜像

- 改善 GitHub 插件安装包的选择与辨识：包名单行展示，悬停可查看完整名称，文件大小以标签展示，选中项使用高亮区分
- 明确插件版本查询结果，避免重复显示发行标题与版本号
- 统一插件开发技能的名称为 `plugin-dev`，补充公开资源入口、目标平台与 GitHub 发布指引
- 修复插件大正文请求被传输或缓冲预算限制的问题，保留完整请求内容；单次调用的元数据编码失败不再中断共享插件会话

## 升级说明

- 从 v3.13.1 升级会自动执行 `0018_plugins.sql`，包含插件、代理位置检测和定时预热所需结构；已发布的 0001–0017 迁移保持原样。升级前备份 PostgreSQL 和部署配置
- 曾运行未发布源码并执行旧版 0018–0021 迁移的开发库，应使用新开发库；这些中间迁移已合并，不能直接复用其 SQLx 迁移记录
- 宿主发行包不内置插件，插件独立安装和升级；仅安装可信插件，插件进程不是不可信代码沙箱
- 固定为 SSE 的账号不承接必须依赖 WebSocket 的协议预热和连接内续接；仅使用这类账号时，Codex 客户端应关闭 `supports_websockets`
- v3.14.1 调整了插件通信合同，使用 SDK `0.1.0`、`manifestVersion: 1` 和 `protocolVersion: 1`；v3.14.0 使用的旧合同插件包不兼容，需要使用配套 SDK 与 CLI 重新构建、打包后安装，不能只修改包内版本字段
