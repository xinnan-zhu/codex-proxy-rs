# v3.22.1

同步官方 main 至 v3.22.1，移除本 fork 的 Turn State 字节观测设计。本说明覆盖从本 fork v3.21.4 升级的更新。

## 用量与性能观测

- 用量记录统一保存请求、调度、传输与恢复观测，迁移并保留历史请求的诊断信息
- 延迟明细区分上游性能、请求观测与传输观测，采集当前响应的关键路径计时，展示响应耗时、引擎耗时、TTFT 和 Token 间隔等指标
- 输出速率使用同一完成响应的上游时间戳计算，缺少有效时间戳时显示「—」；修复性能明细漏采和累计时间混入的问题
- 移除 Turn State 字节采集、数据库字段、使用记录「智商」列和详情中的 Turn State 行，相关请求观测与展示恢复官方实现

## 修复与改进

- 对齐 Codex 0.162 协议：Grok 使用最新增量工具声明，正确更新同名工具及命名空间成员；流内 Retry-After 与官方头部处理语义保持一致
- 账号和 Key 的分组选择改用轻量查询，减少重复聚合；Codex 配置导出与 CC Switch 4.0.4 对齐
- 配置发布复用未变化的插件实例，改进插件状态迁移失败后的恢复，保留进行中请求使用的实例
- 修复 PostgreSQL 事务开始被取消后可能残留事务的问题；迁移或等待迁移锁期间每 15 秒记录等待时间，镜像与 Compose 的启动健康检查宽限期延长至 5 分钟
- 统一管理端重启、SIGTERM 和 SIGINT 的关闭流程，停止监听后结束剩余会话，并保留观测写入与资源清理的收尾预算

## 本 fork 功能

- 保留账号「仅限 Codex 官方客户端」、额度周期费用与重置进度、使用统计模型筛选、每 1M Token 平均费用和系统更新下载代理
- 保留 xAI 正常账号每 5 分钟刷新额度的修复，以及未指定推理强度时新记录显示 `default` 的行为
- Turn State 长度阻断继续保持移除，原始上游协议处理与官方一致

## 升级事项

- 从 v3.21.4 升级会执行官方迁移 `0025_request_observation.sql` 和 fork 迁移 `900008_drop_request_turn_state_bytes.sql`；旧迁移按原字节保留
- 升级前备份数据库并停止共用该数据库的旧版本实例，为历史请求回填预留时间；迁移完成后如需回退，必须同时恢复升级前的数据库备份，不能只切回旧二进制或镜像
- 历史请求的其他观测与诊断信息保留，Turn State 字节值删除；新增上游性能指标及历史推理强度空缺不自动补齐
- `host.drain_timeout_seconds` 不再生效，后台收尾预算由 `host.worker_shutdown_timeout_seconds` 控制；停止或重启会断开尚未完成的 HTTP、SSE 与 WebSocket 会话
- 已有 Compose 部署需同步健康检查配置并重建容器，才能应用 5 分钟启动宽限期
- 手动配置 Codex 时使用完整 config.toml 模板；CC Switch 导入后如需原生生图等模板设置，请核对并补齐对应配置

更新包包含前端、Linux AMD64 二进制、配置模板与封口插件清单，按 Debian bookworm / glibc 2.36 基线构建，供管理端在线更新使用。
