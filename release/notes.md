# v3.24.1

## 修复与改进

- 仪表盘与用量统计采用独立统计数据和持久化聚合，减少大规模历史查询开销，支持历史回填、迟到更新及删除后的统计重建；fork 的「每 $1 可跑多少 M Token」继续仅使用计费完整的 USD 请求
- 请求历史保留账号、客户端 Key 与分组快照，配置变更或删除后仍可查询原始归属；为快照启用前缺失的历史 Key 名称和账号订阅提供一次性补偿
- 修复观测查询超时或取消后过早释放 PostgreSQL 连接预算的问题，名额保留至清理、事务回滚和连接归还完成
- 优化使用记录的精确计数和深分页，增加 Key 与账号筛选索引；统计查询失败时保留页面布局，指标归零并显示原有空状态
- 修复混用 OpenAI、xAI 等 Provider 时已知模型被未知模型兜底抢先匹配的问题，Grok 请求优先匹配声明支持该模型的 Provider
- 修复原生 Responses Lite WebSocket 在前导重试期间丢失中断意图的问题，重试换号后继续转发中断
- 统一管理 API 与界面的缓存输入、缓存写入和推理输出 Token 字段，运行中的恢复租约独立存储

## 升级事项

- 从 v3.23.1 升级将执行官方 `0028_request_analytics.sql`、`0029_usage_indexes_and_identity_snapshots.sql` 及 fork 的 `900010` 观测投影兼容迁移；已发布迁移保持不变
- **首次迁移可能需要数分钟或更久，迁移完成前服务不会开始监听**。请提前备份数据库、停止旧版本写入，预留维护窗口以及新索引和 WAL 所需的磁盘空间；等待迁移完成，避免反复重启
- 统计历史回填在后台进行，回填完成前未覆盖范围的统计可能暂时不可用；原始请求历史保留。完成迁移后不能直接换回旧二进制运行
- 管理 API 的 `cachedTokens`、`cacheWriteTokens`、`reasoningTokens` 分别更名为 `cachedInputTokens`、`cacheWriteInputTokens`、`reasoningOutputTokens`；自定义客户端和报表需同步调整
- 补齐的历史名称与订阅来自迁移时仍存在的配置，不保证等于请求发生时的值；已删除配置或无法补齐的字段保持未知
